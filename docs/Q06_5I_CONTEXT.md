## 当前问题与完成范围

H 已提供固定 50 候选的重排，但原始 logits 不能直接进入旧余弦阈值，也没有统一的证据数量、重复控制与生成输入预算。本轮在 H 已选流程上加入完整片段选择，冻结最终提示、证据、模型参数和预算，并在实际发送前再次核验。

验证仅使用 20 个开发题：18 个可回答题计算证据指标，2 个证据不足题只记录选择与预算；预留 6 题没有执行。没有重新推理 H、没有编码 embedding，没有调用生成 API，也没有把此前 B 的外发授权扩展到新的片段。生成行为仅以模拟传输验证。

## 固定策略

[配置](../config/q065i_context.json) 在预览前固定，按 H 的排序顺序扫描其相同 50 个候选：

1. 最多 10 个完整片段，每篇最多 6 个。不强制最低文献数、不翻译或扩展邻近片段，也不利用标准答案决定选择。
2. 对 chunk_id、规范化空白后的完整文本去重；保留原文不做裁剪。相同文献/页的来源字符区间按并集计算，若新片段超过 50% 的来源字符已覆盖，则跳过。不同论文、不同页不算来源跨度重复。
3. 每加入一个片段，重建完整提示和请求体；若超输入预算，跳过整个片段，继续寻找后续能完整放入的候选。问题与模板本身已超限时直接报错。
4. 保留每个候选的原排名、选入状态和排除原因；所有选中片段保留完整 chunk_id/doc_id、原始文本和原文位置。单篇上限是工程控制，不是对科学相关性的判断。

该顺序可能把较靠后的候选提前，本轮最远使用 H 第 39 名。它始终来自原 50 候选，没有扩充候选池，也没有把低排名片段认定为已验证支持。

## 预算的定义与限制

当前第三方平台的精确 tokenizer 和隐藏聊天模板未在本地验证。因此采用**完整 HTTP JSON 请求体序列化后的 UTF-8 字节数**作为保守准入估算，并明确保存 `provider_exact_input_tokens: null`、`counter_is_provider_tokenizer: false`。

计入完整提示中的系统边界说明、问题、JSON 证据、引用 ID、标题、页码等字段，以及消息角色和模型调用参数；JSON 非 ASCII 转义也计入字节数。Authorization 密钥和 HTTP 头不写入快照。它不是 tokenizer 实测值，不使用“字符数/4”推算，也不声称是供应商精确 token 上限。

| 本地预算项 | 固定值 |
| --- | ---: |
| 完整请求输入字节估算上限 | 32,000 |
| 实际 `max_tokens` 输出请求上限 | 4,096 tokens |
| 协议/隐藏模板预留 | 1,024 估算单位 |
| 输入估算 + 输出 + 预留的本地准入总上限 | 40,000 估算单位 |

输入字节按一字节一估算单位保守预留，与输出 token 数相加只用于本地准入，**不能称为供应商精确总 token 数**。1,024 余量不证明隐藏模板实际开销；40,000 也不是已核实的平台上下文长度。该方案保证本地请求大小可审计，不能保证第三方实际 token 数、容量或费用。真实调用时沿用 B 的 usage/attempt_history 记录供应商报告用量，后续获得可验证 tokenizer 时应替换计数器并重新冻结候选，不能回填虚构 token 数。

`PreparedPrompt` 增加可选冻结预算；旧流程没有预算时继续生成原格式快照，B 的历史提示逐字比较保持兼容。冻结预算绑定完整 payload、策略哈希与允许的调用参数。生成器和 `send_request` 都在发送前核对，所有重试再次核对；变更模型、思考模式、温度、输出上限、提示或消息将拒绝发送，不会自动放宽预算。

没有片段能放入时保留 `no_whole_chunk_fits_policy` 原因并走原 Q06 的本地无证据回答，不请求 API；参数错误和问题/模板超预算直接报错，不伪装成科学证据不足。引用格式与体系边界提示未改动。预算冻结的是请求输入，不能证明非空材料科学支持充分。
