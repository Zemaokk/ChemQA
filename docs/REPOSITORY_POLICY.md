# 仓库文件与上传策略

2026-10-08。本次只整理 Git 跟踪边界，不改动运行实现、冻结实验和本地数据，不提交、不上传、不重写历史。

## 应跟踪的内容

- `src/`、`main.py`、`scripts/`、`tests/`：实现、可复现操作入口与合成测试。
- `pyproject.toml`、`uv.lock`、`requirements.txt`、`.python-version`：依赖与运行环境；应用项目需要提交锁文件。
- `.env.example`、`config/`：无密钥的模板、模型参数、版本化运行清单与协议。
- `evaluation/`、`docs/`：题库定义、评分规则、摘要、验证和采用记录。体积小且具有追溯价值；这些文件可能含文献摘录与本机路径，跟踪并不代表所有内容已获准公开。
- `qa_testing/`、`heatmap_visualization/` 中的脚本和说明。
- `data/README.md`：告知数据准备与恢复要求。
- `doc/report.pdf`：已有作者报告，作为编写产物保留；它不是当前质量验收依据，当前状态以 README/技术报告为准。不屏蔽所有 PDF 或图片，以便未来按需跟踪正式文档与人工选择的演示资源。

## 只在本地保存的内容

| 内容 | 原因与保存方式 |
| --- | --- |
| `.env*`（除 `.env.example`） | 凭据及机器配置，不上传 |
| `.venv/`、缓存、构建目录、日志、编辑器状态 | 环境或运行可再生成 |
| `data/raw_papers/` | 大体积研究文献，源码不应捆绑整份语料；独立备份 |
| `data/processed/`、`data/vector_db/` | 抽取全文与大索引，可重建但冻结资产仍需独立保留 |
| `models/` | 模型权重/缓存；记录模型 ID、revision 与参数，而非上传权重 |
| `output/` 与旧测试输出目录 | 批量问答、索引候选、运行明细、旧回答和生成图片；原始实验资产独立归档 |
| `example_answers/` | 旧的批量生成答案；当前可核查演示保留在 `docs/DEMO.md` |

不全局忽略 JSON、数据库扩展名、PDF 或图片，避免掩盖必要的配置、测试夹具和正式文档。新增自定义输出位置时，应增加精确目录规则。
