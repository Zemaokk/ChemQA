## 历史处理方案

采用“保留现有开发仓库，另建无历史源码快照”的方式：

1. 已撤销的历史凭据作为脱敏审计事项保留，原仓库现有提交和分支不改变。
2. 通过 `scripts.prepare_source_release` 复制当前源码、测试、文档、依赖锁与空密钥配置范例到全新输出目录，逐文件记录 SHA-256，并再次扫描实际复制字节。已存在的目标拒绝覆盖。
3. 排除 `.git`、`.env`、文献 PDF、向量/处理数据、模型权重、本地输出和历史答案目录。批量脚本目录只复制脚本及 README。生成物位于忽略的 `output/source_releases/`。
4. 后续公开时以该快照作为新仓库或源码包的起点，不复制原 `.git`，不推送原分支或 tags。此次仅生成本地快照，没有创建 Git 提交、远程仓库或发布。

这条路径不会删除已存在于远程、其他克隆或缓存中的旧历史；失效依赖原平台撤销，已由用户确认。若以后需要沿用原仓库完整历史公开，应另行确定历史重写范围、备份及远程处理方案；本项没有执行这类操作。无历史快照提供源码隔离，不构成对文献、权重或其他内容再分发权利的审查。

快照不含可运行检索所需的 PDF、索引和模型缓存，须自行提供兼容数据，再按 Q08 显式选择路径。快照也不自动包含忽略或未纳入源码白名单的其他文件。

## 可重复检查

从项目根目录运行：

```bash
# 当前工作区 + 未忽略的新源码；干净返回 0
uv run --locked python -m scripts.audit_secrets

# 精确检查将提交的 Git 暂存内容，避免工作区干净但暂存区仍有凭据
uv run --locked python -m scripts.audit_secrets --staged

# 历史检查：当前原仓库仍有历史匹配，预期返回 1
# 输出不含凭据值；保留旧审计记录时使用新的报告路径
uv run --locked python -m scripts.audit_secrets --history \
  --report /tmp/chemqa-secret-history-audit.json

# 创建新的、无 Git 历史的源码快照；打印实际目录
uv run --locked python -m scripts.prepare_source_release

uv run --locked python -m unittest discover -s tests -v
uv run --locked ruff check .
uv run --locked ruff format --check .
```

扫描器覆盖 `sk-` 加至少 16 个字母、数字、下划线或连字符的模式。默认检查已知文本扩展名和少数配置文件名；历史模式只检查本机 `git rev-list --all` 可达的文本 blob，超过 2 MiB 的历史文本仅列出跳过记录。二进制、未知扩展名、忽略的本地文件、reflog、不可达对象、远程独有 refs 及其他克隆不在该检查范围，不能将零匹配表述为全面安全证明。

历史报告明确保留 `history_clean=false`；旧密钥撤销确认与无历史快照是本项采用的处理方案。审计和快照不是自动安装的 Git hook，也不会自动阻止其他工具提交；提交前需自行运行 `--staged`。
