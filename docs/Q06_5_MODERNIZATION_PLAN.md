## 1. 如果今天重新构建，我会采用什么方案

推荐目标：**结构化文献处理 → 多语言向量与 BM25 混合召回 → RRF 融合 → 小型 reranker → 有预算的证据组织 → 云端 LLM 回答 → 引用与体系边界检查**。

ChemQA 是使用预训练模型的领域 RAG 系统。此次更新以模型选型、推理配置和检索工程为主；基座训练、微调、Agent、GraphRAG、专用数据库服务与多模态全文问答暂列后续候选。新增组件必须能通过固定问题集说明价值。

“主流”在本计划中指仍受维护、官方接口明确、适合中英文学术检索、可在本项目环境复现的方案。下面是建议的初始配置，尚未证明在 ChemQA 上优于现状；实施时还要重新核实模型 ID、版本及可用性。

## 2. 当前状态与建议配置

| 环节 | 当前实现 | 建议起点 | 决策依据与边界 |
|---|---|---|---|
| 回答模型 | 本机第三方 `DeepSeek-V4-Flash`，显式非思考，20 题真实执行基线完成 | 日常使用 `deepseek-flash`；固定困难题另测 `deepseek-v4-pro` | 保留现有供应商，先处理接口时效性，再比较回答质量与费用 |
| Embedding | multilingual MiniLM，384 维，实际输入上限 128 token | 首选试验 `Qwen/Qwen3-Embedding-0.6B`，1024 维；`BAAI/bge-m3` 作备选 | 面向中文提问、英文文献；最终依据领域检索与本机资源测试选择 |
| 分块 | 随旧模型按 tokenizer 短分块，重叠 16 token | 段落/章节优先，目标 512 token、重叠 64；开发集比较 256/512/768 | 将片段目标长度与模型硬上限分开，保留完整条件与来源位置 |
| 召回 | 余弦检索，top 10 | Dense top 50＋BM25 top 50，RRF 合并去重 | 精确术语、化学式与跨语言语义分别进入候选；参数通过开发集调整 |
| 重排 | 无 | `Qwen/Qwen3-Reranker-0.6B`；先重排融合后的前 30 条 | 与无重排对照；本机资源或延迟不合适时保留可关闭配置 |
| 证据输入 | 前 10 条证据；未独立管理生成输入预算 | 最终约 6–10 条，证据文本预算先设 8k token | 用生成侧计数/有来源的估算独立管理预算，完整请求另留系统指令与输出空间 |
| 输出预算 | `max_tokens=4096`，建连 10 秒/读取 120 秒 | 非思考模式起点 4k 输出；思考模式先测试 8k 总输出预算 | 按官方参数含义处理推理开销，记录截断、耗时、token 与失败状态 |
| 索引 | JSON 保存全部向量与元数据 | FAISS `IndexFlatIP`＋归一化 float32 向量，SQLite 保存证据/元数据 | 当前约 2.6 万片段先用精确检索；安装不适配时使用 NumPy 二进制向量后端 |
| PDF | PyMuPDF 文本提取与定位 | PyMuPDF 保留；抽样比较 Docling 的布局、表格与 OCR | 先检查双栏、表格、上下标、单位与条件，不直接全库替换解析器 |
| 运行环境 | Python 3.12，uv；Sentence Transformers 6.1.0 / Transformers 5.19.0 | 保留已验证的 6.1.0 兼容栈；后续版本需重新回归 | 移除阻碍模型支持的旧版本限制；其余依赖按兼容性、维护与实际问题更新 |

依据核查：

- DeepSeek 当前官方列出的模型 ID 是 `deepseek-flash` 与 `deepseek-v4-pro`；Flash 对应 V4.1，旧 `deepseek-reasoner` 已在官方升级公告中列入退役安排。旧配置需要迁移；本轮未实测账户侧请求。[当前模型表](https://api-docs.deepseek.com/quick_start/pricing/)、[官方升级公告](https://api-docs.deepseek.com/news/news260424/)
- DeepSeek 现有思考开关与 effort 参数应显式配置。思考模式下 `temperature` 等参数不生效，不能继续将当前 `0.3` 当作有效控制。先以 Flash 非思考模式建立低延迟基线，复杂题再比较显式思考模式；每种实验固定模式与预算。[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)
- Qwen3 Embedding 0.6B 支持多语言、32k 输入与默认 1024 维向量；查询侧需要遵循官方 instruction/prompt 用法，文献侧单独编码。32k 是能力上限，本项目仍从约 512-token 片段起步。[官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)
- BGE-M3 支持多语言、1024 维与 8192-token 输入，作为替代候选；不预先断言其本机速度或领域质量。[官方模型卡](https://huggingface.co/BAAI/bge-m3)
- Qwen reranker 需要遵循其输入模板与评分接口；输出分数即使映射到 0–1，也不代表科研结论可信度。[官方模型卡](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)
- FAISS 内积检索需要查询与索引向量均归一化，才能保持 Q04 的余弦含义。[官方度量说明](https://github.com/facebookresearch/faiss/wiki/MetricType-and-distances)
- 截至本次核查，Sentence Transformers 的稳定发布为 6.1.0；本次已通过现有回归及新模型烟测后锁定；结果见 Q06.5-C。[官方发布信息](https://pypi.org/project/sentence-transformers/)
- Docling 提供 OCR 与表格处理能力；是否改善本库提取结果仍需页级对照。[官方 OCR 示例](https://docling-project.github.io/docling/_generated/examples/full_page_ocr/)

## 3. 更新时必须保留的正确性约束

1. PDF 身份、页码、位置与原文片段可核查；标题或检索别名属于派生字段，不改写引用原文。更换解析或分块策略会产生新片段身份，历史结果保留其旧索引快照。
2. Embedding 的 query/document 编码分别适配；查询指令、特殊 token、reranker 输入模板都计入对应模型的预算。禁止静默截断。
3. 更换 embedding 必须重建对应索引。模型 revision、维度、归一化方式、分块及解析版本进入 manifest；查询与索引不兼容时明确失败。不能把新向量和旧向量混排。
4. 混合检索保存各路排名、融合结果与重排分数；化学式、上下标、单位的原始表达与检索规范化形式分开保存。BM25 对中英文的分词与跨语言不足需要专门检查。
5. Q05 的完整证据 ID、冻结提示快照，以及 Q06 的空证据停止、体系边界和证据不足说明继续生效。相似度、重排分数与“证据支持结论”分别判断。
6. 旧阈值不跨模型沿用。按开发集重新选择检索参数；最终保留集不参与反复调参。
7. 所有候选索引在独立目录构建，校验通过后再切换默认配置。保留旧模型 revision、索引及运行记录，以便回退。
