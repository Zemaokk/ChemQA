# Q01：文献、片段身份与引用映射

日期：2026-10-06  
状态：完成本项实现及本地验收；未调用在线回答 API。

## 问题与复现

原实现将局部 `chunk_index` 当作全局身份。构造两个片段 `A.pdf / 0` 和 `B.pdf / 0`，回答 `A claim [Ref 0]` 被格式化为 `A claim [2]`；分析器只保留一个映射条目，并把引用归给 B。不同文献的局部编号相同会覆盖字典，引用对应关系因此不可靠。

## 验收标准

1. 不同 PDF 的同编号片段具有不同稳定 ID；格式化与引用分析不能串文献。
2. 同一份 PDF 改名或复制后仍保持内容身份；重复导入相同片段不新增索引记录。
3. 内容或分块改变时产生新片段身份，已有 ID 与文本不匹配时拒绝使用。
4. 身份从 PDF 提取、分块、索引、检索保留到引用映射和回答记录。
5. 含糊或未知的 `[Ref ...]` 保持可见，明确报告无法定位，不推断为某篇文献。
6. 历史数据迁移先备份，保留每个保留片段的原文本及原向量，不调用 embedding 或回答 API；再次迁移不改变文件。

## 方案与取舍

- `doc_id = doc_ + SHA256(PDF 原始字节)`：这是 PDF 文件内容身份，不是 DOI 或抽象论文身份。同一篇论文的不同 PDF 版本会得到不同 ID；不同文件名但相同字节得到同一个 ID。
- `chunk_id = chunk_ + SHA256(JSON([identity_version, doc_id, chunk_index, text]))`：使用完整 SHA-256，并把身份方案版本纳入计算。局部序号只作为位置辅助，不再单独作为引用主键。
- 当前身份版本为 `sha256-pdf-chunk-v1`。采用精确文本，不为身份生成额外清洗文本；今后清洗或分块改变会产生新 ID。
- 重复片段按稳定 ID 合并，保留第一个记录与原向量，并合并来源别名 `sources`。更换分块方式后新增的片段不会自动删除旧版本；重建与版本管理仍属 Q08 的后续范围。
- 新回答使用 `[Ref 完整chunk_id]`。显示层仍采用按文献分组的 `[1]`、`[2]`，同时保留文献 ID 与片段 ID 的映射。
- 兼容旧的 `[Ref 局部编号]` 或 `[Ref source]` 仅限它们能唯一定位一个片段时；不能唯一定位时标为 `【未解析引用：原标记】`，报告中记录候选 ID 和原因。
- 数字显示编号是本次回答中的排版编号，不是持久身份。本项只明确已有 Ref 格式与 chunk_id 的最小接口；提示词仍直接接受上下文字典，Q05 的结构化证据序列化继续待处理。

## 实际改动

- `src/knowledge_base/identity.py`：统一生成、验证和归一化身份，兼容扁平索引与嵌套片段元数据。
- PDF 提取使用同一份读入字节进行解析与哈希，分块保留身份；构建索引和增量导入按 ID 去重。
- 检索返回完整记录；字符串上下文包含完整 chunk_id 引用标记。
- `src/qa_system/evidence.py`：格式化器和分析器共用唯一引用解析逻辑，不再用局部序号覆盖映射。
- Markdown 回答包含证据身份映射；同名 `.evidence.json` 保存问题、原始模型回答及检索上下文的完整片段文本、身份、来源和显示编号。仍沿用旧输出文件名，该限制继续归 Q08。
- 取消缺少文本的古老索引格式的自动转换：旧逻辑会把整篇 PDF 文本当成片段文本。现在明确要求显式重建，不在加载时自动覆写文件。
- `scripts/migrate_q01.py` 默认只预览；`--apply` 在校验处理文件和向量文件逐条一致后备份并迁移。两份 JSON 各自以临时文件替换，并非跨文件事务；如中断可从完整备份恢复。
